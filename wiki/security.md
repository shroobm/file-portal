# Security Posture

**If you read nothing else: THE REPO IS PUBLIC on GitHub** (`curl -s https://api.github.com/repos/shroobm/file-portal` → `"private": false, "visibility": "public"`, run 2026-08-23; remote per `git remote -v`). Everything tracked here is world-readable: no personal data in tracked files, no secrets ever, and profile personal content lives only in the gitignored private layer (wiki/profiles/README.md:11-15, .gitignore:57). The trust perimeter is the Tailscale tailnet — no public listening ports anywhere (docs/06-security-model.md:15-16) — and since 2026-09-30 the web servers enforce it themselves: each listens only on a loopback or Tailscale address, refuses any peer outside both, and refuses a proxied request or one a web page on another site sent (§7; over plain http the `Origin` rule and the GET rule do that, not `Sec-Fetch-Site`). The core is genuinely sound: a strict widget CSP, an 8-permission capability grant, path-validated IPC, and a tracked-file secret sweep that comes back clean. The honest gaps: two loopback HTTP servers mutated files with zero request authentication until S108 gave them a token — against the repo's own written rule (docs/38:756-758; §3 is that pre-S108 record, §7 is today's) — the lane that parses untrusted PDFs has no dependency manifest, `Cargo.lock` is gitignored, all three systemd units carry zero hardening directives, and there is no SECURITY.md. None of the gaps is internet-reachable; remediation is owned by roadmap catalysts C4 (the bench auth token, wiki/roadmap.md:33) and C5 (the standards slate, :34).


> **S108 update (2026-08-23):** the loopback gap below is now GATED: bench.py and room_chat.py require `X-FP-Token` on every mutating route (403 fail-closed, `fb2a919`), and the widget passes a per-launch token (`?token=`, lane G). The 'zero Origin/token checks' lines below describe the PRE-S108 state; severity notes still apply to hand-started servers run without `--token` (which now refuse mutations).

The servers now refuse them on their own: §7 says what is refused, by which check, and which 403 reason shows it. A third round closed the gap an independent verifier found: browsers send Fetch Metadata only to https and loopback, so over plain http to the tailnet every `Sec-Fetch-Site` rule is inert and the `Origin` rule and the GET rule carry the lock (§7). §§1-6 were last re-measured 2026-08-23; §7 was read in the working tree on 2026-09-30 (Observed in source, not by a request: the code is uncommitted on top of 61e3552, and a service started earlier runs the code it started with; UNREAD which running processes carry it). The `bench.py` and `room_chat.py` line numbers in §3 and §4 below predate S108, the S215 Host pin and these locks.

## 1. Trust model: the tailnet is the perimeter

- **No public listening ports.** "no port is opened on any router or public interface. All traffic rides the Tailscale WireGuard tunnel" (docs/06-security-model.md:15-16).
- **Identity is the tailnet node**, not keys or passwords: Tailscale SSH authenticates by node identity, gated by the Tailscale account login + optional 2FA (docs/06:17-19). The residual risk docs/06 itself names: a compromised Tailscale account inherits the tailnet (docs/06:31-33).
- **Privilege ceiling on the Linux side:** the ACL restricts SSH `users` to a non-root account — a fully compromised Windows app "can only do what your unprivileged Linux user can do" (docs/06:21-23). The allocator writes only inside `~/file-portal/...` and accepts a *category*, never a destination path (docs/06:24-27).

## 2. What is sound

- **Widget CSP** — `default-src 'none'; script-src 'self'; style-src 'self'; style-src-attr 'unsafe-inline'; connect-src ipc: http://ipc.localhost` (windows-widget/src-tauri/tauri.conf.json:24). No remote script, style, or connect surface.
- **Minimal capability grant** — 8 permission strings (of the whole Tauri v2 permission catalog), all `core:*` window/webview basics, scoped `"windows": ["main"]` (windows-widget/src-tauri/capabilities/default.json).
- **IPC input validation** — `source` names from the frontend are rejected on any path separator: `source.contains(['/', '\\', ':'])` at assay.rs:220, and the same guard repeated at :285 and :345 (windows-widget/src-tauri/src/assay.rs). The engineering-file opener is a closed allowlist: "the match below IS the allowlist" — named targets only, never an arbitrary path (windows-widget/src-tauri/src/line.rs:333-342).
- **No committed secrets** — probe: `git grep -IE` over all tracked files for 5 secret shapes (`AIza[0-9A-Za-z_-]{35}`, `ghp_[A-Za-z0-9]{36}`, `sk-[A-Za-z0-9]{32,}`, `tskey-…`, `BEGIN (RSA|OPENSSH|EC|DSA) PRIVATE KEY`) → **0 tracked files match**. Probe controlled first per contract: a planted positive file hit 3/3 patterns, a negative file hit 0. Scope: tracked files at 1790554 only — untracked and history not swept.
- **GEMINI_API_KEY never touches argv** — read from env (windows-converter/analyst.py:116), sent as an `x-goog-api-key` request header (analyst.py:132); the code's own comment records the fix: the key "is never on any argv (the curl form put it there…)" (analyst.py:112). ⚠ **Stale-fix trap:** docs/37-next-stage-plan.md:89 still lists F-13 "Gemini key in curl argv (CWE-214)" as **CONFIRMED** — the record lags the code. Trust analyst.py, not the F-13 row.

## 3. The gaps

Each one cited; none is disputed by any register.

- **Two loopback servers mutate files with zero Origin/token/CSRF check.** The repo's own rule, verbatim: "Loopback is a network boundary, not authentication; another local process may still be hostile. Any future route that mutates files requires the same path/authority scrutiny as a native command." (docs/38-file-portal-full-system-scope.md:756-758). Against that rule:
  - **prototypes/repair-bench/bench.py** — `do_POST` (:1411) parses the body with `json.loads` regardless of Content-Type and with no origin check (:1414-1415). `/api/md` (:1424) overwrites the served bundle's markdown body; `/api/open` (:1438) opens `payload["path"]` — an **arbitrary filesystem path taken from the request body**. Binds 127.0.0.1 (:1500).
  - **windows-converter/room_chat.py** — `do_POST` (:467) same shape (:468-469). `/api/load` spawns a llama-server subprocess (:317-319) and writes `chat-hold.json` (:88), which defers pipeline converts — so an unauthenticated local POST can hold the GPU lane. It sets a CSP on its *own* pages (:445-449) but validates nothing about who is POSTing. Binds 127.0.0.1 (:535).
- **windows-converter has NO dependency manifest** though it parses untrusted PDFs: `git ls-files windows-converter | grep -E 'pyproject|requirements'` → 0 of its 18 tracked files. The interpreter is an out-of-repo venv; the environment is unreconstructable from the repo. (Every Linux Python lane has a pyproject.toml.)
- **Cargo.lock gitignored, package-lock.json tracked** — `.gitignore:5` ignores `windows-widget/src-tauri/Cargo.lock`; `git ls-files windows-widget/package-lock.json` returns it tracked. The Rust build is unpinned while the JS build is pinned — backwards for the lane that ships the binary.
- **All three systemd `.service` units carry zero hardening directives** — probe: grep for 12 directives (`ProtectSystem|ProtectHome|NoNewPrivileges|PrivateTmp|ReadWritePaths|CapabilityBoundingSet|RestrictAddressFamilies|SystemCallFilter|ProtectKernel*|LockPersonality|MemoryDenyWriteExecute`) → 0 matches in file-portal-converter.service (23 lines), file-portal-vault-fixity.service (10), file-portal-allocator.service (22). The converter unit hosts the vault exporter (linux-converter/converter/main.py:304-311) — the vault's only writer; the fixity unit is report-only.
- **No SECURITY.md** — `ls SECURITY.md` fails; `git ls-files | grep -i security.md` is empty. docs/06 is a design doc, not a disclosure policy — and the repo is public.
- **No per-file SHA-256 transport inventory before vault commit** — docs/38's own words: the streaming tar/SSH hop has "no arrival inventory or package digest … currently enforced" (docs/38:314); "this remains an explicit gap" (docs/38:783; risk row :892).

## 4. Severity honesty

The loopback-CSRF gap requires **the server running AND a hostile local page or process**. room_chat.py binds 127.0.0.1 only (room_chat.py:597, 2026-09-30) and the bench binds 127.0.0.1 plus, when the Scanner starts it, one literal tailnet address (`--also-bind`, bench.py:2686; §7); nothing is router-forwarded (docs/06:15-16) — this is not internet-reachable. The realistic vector is a hostile web page in the operator's browser firing a cross-site "simple request" at the known local port (the handlers parse any body as JSON, bench.py:1414-1415), or any other process on the machine. The bench is a prototype the operator starts deliberately; room_chat runs while the Room assistant is up. Real gap, local blast radius. **Since 2026-09-30 that vector is closed twice over for the bench** (a foreign `Origin` or `null` is refused on every method, and the token is read from a header only; §7). room_chat.py has the token alone (`token_gate` before any POST dispatch, room_chat.py:510): a simple cross-site POST cannot carry the `X-FP-Token` header, so it is refused there too; what stays in scope is a local process that learns the token.

## 5. The untrusted-input boundary

PDFs are the system's attacker-controllable input, and they are parsed **in-process, unsandboxed, with the operator's full user rights**:

- `import fitz`/pymupdf in 8 tracked .py files (probe: `git grep -lE '^import fitz|import pymupdf' -- '*.py'` → 8 — convert_and_ship.py, fidelity_audit.py, figure_coverage.py among them; unfiltered the probe also hits 5 docs/prose files) plus deferred imports in bench.py (:417, :869); Marker runs as a spawned subprocess of the same user.
- What limits exist are **wall-clock only**: kill at `max(3600, pages * 20)` s (windows-converter/convert_and_ship.py:690), frozen-stall kill at 900 s (:95, :722), outer 6 h cap (windows-converter/watch_and_convert.py:166).
- What does not: no memory cap, no privilege drop, no filesystem jail. The widget's Job Object is lifetime control — its only limit flag is `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` (windows-widget/src-tauri/src/watcher.rs:27, :40) — not a sandbox. A pymupdf parser exploit executes as the operator (unverified that one exists; the exposure shape is what is being recorded).

## 7. Tailnet-only reach (2026-09-30)

**What is refused, by which check.** Four checks sit in every File Portal web server: the bench and the two ThinkPad feeds (this repo) and, in the private layer, the Desk, Control, Scanner and PORTAL. All were read in source on 2026-09-30, after the plain-http round (Observed; no request was sent to any live port and no browser was used). Each server's suite has a negative control per rule (the code lanes' reports; not re-run by this docs edit).

| Lock | Refuses | Shows as |
|---|---|---|
| 1 Bind | listening on anything but a literal loopback or Tailscale address (127.0.0.0/8, ::1, 100.64.0.0/10, fd7a:115c:a1e0::/48): `0.0.0.0`, `''`, `::`, a LAN or public address, a name. Checked before a socket exists (`bind_ok` bench.py:2288, `serve_on` :2819) | the process exits at start: the bench with argparse exit 2, "is not a literal loopback or Tailscale address" (`_bind_arg` :2838); the feeds with "refusing to start: BIND ..." (indexer serve.py:564, dashboard :564) |
| 2 Peer | a connection from outside those ranges, judged before any request byte is read, for every method (`Handler.handle` bench.py:2534, `peer_ok` :2277) | a bare `403` with no body, connection closed; a console note naming only the address (the first 5, then every 1000th) |
| 3 Request | what a page in his own browser, or a proxy, can send: his devices are tailnet peers, so lock 2 admits them. A `Host` that is not this machine's own name; an `Origin` that is foreign or `null`; a proxy or `Tailscale-*` header; where the browser sends it, `Sec-Fetch-Site: cross-site` | a 403 or 421 whose JSON body names the rule (per server, below) |
| 4 Proof / no side effect | a GET or HEAD that changes something, from a request that cannot show it came from our own page or tool. The first remedy was to take the side effect out of the GET (most servers did); where one stays, the request must prove itself | `403` reason `unproven-origin` (bench, Control, feeds); the Scanner serves the answer and writes nothing |

**Where each rule fires (the plain-http gap).** A browser sends Fetch Metadata (`Sec-Fetch-Site`, `-Mode`, `-Dest`) only to a potentially trustworthy URL: https, or 127.0.0.0/8, ::1, localhost. These servers are reached over plain http at a tailnet address or a MagicDNS name, so there a browser sends none of it: **the `Sec-Fetch-Site` rule fires only on https and loopback, and on the tailnet it is inert.** What plain http does send: an `Origin` on every POST, PUT, PATCH and DELETE (a same-origin one too) and on any cross-origin fetch; none on a GET navigation, `<img>`, `<script>`, `<link>`, `<iframe>` or form GET; a `Referer` by the default referrer policy (a foreign page can suppress it, never forge one naming our host). No server here answers CORS, so a foreign page can never read an answer, and a request that is not "simple" (a custom header; a `Content-Type` other than text/plain, urlencoded or multipart; a method other than GET, HEAD, POST) dies at the preflight. What a page in his browser can still fire is a simple request: a blind GET (no `Origin`, maybe no `Referer`), or a simple POST carrying its own foreign `Origin` or `null`. So on the tailnet the locks that hold are the `Host` pin, the **`Origin` rule** (a present `Origin` must be ours, `null` refused; an `Origin`-less POST is a non-browser client and passes), the **GET rule** (no GET changes anything, or it needs proof: `Sec-Fetch-Site` same-origin, same-site or none when sent, else a `Referer` whose host passes the `Host` check, else a custom header `X-FP-Local` that a cross-site page cannot add), the content types a write route takes, and `frame-ancestors` (every server but the bench sends it: itself for the Control and PORTAL, itself plus the Control shell for the Desk and the Scanner, `'none'` for the feeds). The `Tailscale-*` refusal (lock 3) covers **HTTP-mode Funnel only**: a TCP-mode funnel carries no header and reaches a server from 127.0.0.1 like any local client; `security/lockdown_check.py` (checks D4 and T1, private layer) is what catches any Funnel.

- **Bench** (bench.py): `Host` must be 127.0.0.1, localhost, ::1, the address the request arrived on, or a `--host` name (the Scanner passes the machine's tailnet names), else **421** `{"error": "this bench answers only to its own names ..."}` (`host_ok` :2333); a second `Host` header is 421 too (`host_header_ok` :2341). On its tailnet listener 127.0.0.1, localhost and ::1 are not its own names in an `Origin` or `Referer`. Any `Forwarded`, `Via`, `X-Real-IP`, `X-Forwarded-*`, CDN marker or `Tailscale-*` header gives **403** `{"error": "this bench answers direct requests only ..."}` (`PROXY_MARKERS` :2372). Then `page_refusal` (:2499): an `Origin` that is not the bench's own (http, one of its names, its own port; `null`, a second `Origin`, a sibling port, https refused) gives **403** reason `origin`, on every method; a `Sec-Fetch-Site` other than same-origin, same-site or none gives `fetch-site`, except a GET navigation of `/` into a window or frame (the Control's Repair tab frames it); the one GET with a side effect, `/api/evidence` (spawns the OK-15 collector, caches its report), needs proof (`proof_ok` :2486) or gives `unproven-origin`. It stays a GET because OK-15 is signed as a read route, and a test pins that. Then the `X-FP-Token` gate (:2254) on every POST and on the evidence GET gives **403** with the remedy; the token is read from the header only, never `?token=`. Every other GET reads (an in-memory cache fills, no answer changes; the suite checks a byte snapshot). The bench sets no CSP and no `frame-ancestors`.
- **Desk** (private): no GET or HEAD route changes anything, which its suite pins by a scan of the GET handler and a before/after snapshot of the store over three plain-http header shapes. Each write route refuses a present foreign, `null` or empty `Origin` (**403** reason `origin`) and takes only `application/json` (an attachment: an image type), else **415**, so a simple text/plain, form or multipart POST is stopped even with no `Origin`. It reads no `Referer`, and asks for no `X-FP-Local`, because no GET needs proof.
- **Control** (private): its pages change nothing and stay open to a typed or bookmarked visit. The two JSON routes that spawn `git` or ask PORTAL (`/api/home`, `/api/grid`) are proven-only: **403** `unproven-origin` unless `Sec-Fetch-Site` passes when sent, else exactly one `Referer` whose host is ours, else `X-FP-Local`; the pages and the state pump's probe send it. The Library graph's refresh, which used to ride a GET (it asks the ThinkPad feed with a token and writes a cache file), is now a POST behind the `Origin` rule, at most once a minute; the GET returns the last copy and fetches and writes nothing, so a typed visit no longer refreshes the graph.
- **PORTAL** (private; its own repo): every write is an `Origin`-guarded POST, and no GET or HEAD changes anything. The deliverable GET used to record a delivery; it now only serves the file, and the page POSTs the record itself (how: download, open or share). An `Origin` or `Referer` of ours means http, one of this machine's names and PORTAL's own port (a page on :7077 or :7170 is not ours), and a second `Origin` or `Host` header is refused. A backstop: a request whose `Referer` names another site is refused (**403**, a sentence) except a GET or HEAD of a page route, so a link on another site opens a page and never an `/api/*` path.
- **Scanner** (private): every POST (journal edit, rescan, bench, view pointer) refuses a present `Origin` that is not one of its own pages on its own port (`null` included; **403** reason `foreign-origin`), then on its tailnet listener needs the per-start page key in the `X-FP-Token` header (**403** "X-FP-Token missing or wrong"), then a `Sec-Fetch-Site` of none or same-origin when sent (same-site is refused: it ignores the port). A `Host` pin gives **421** (a second `Host` header too); a second `Origin` header **403**; a proxy header **403**. On its tailnet listener 127.0.0.1, localhost and ::1 are not its own in an `Origin` or `Referer`. The GET that used to start or swap the bench is now a bare redirect to its `/repair` page; reading the human journal no longer makes its directory; the page-render disk cache is written only for a request that proves it is ours (a foreign one is served the same bytes and writes nothing).
- **The two ThinkPad feeds** (linux-indexer, linux-dashboard; both bind 127.0.0.1 behind `tailscale serve`): a request carrying `Tailscale-Funnel-Request`, Tailscale's mark of a request that came from the public internet through Funnel (HTTP-mode only), gets the bare 403 before any route, token or body, whatever its value, on every path including /health (`parse_request`, indexer serve.py:338 and :353, dashboard :393 and :408). Behind `tailscale serve` every peer looks like 127.0.0.1, so lock 2 cannot tell a tailnet caller from a public one there; that header does (and a TCP-mode funnel it cannot). The `Host` must be loopback, localhost or this machine's own tailnet name (read once at start from `tailscale status --json`; if that fails the pin loosens to any single-label or `*.ts.net` name and prints one line), else **403** reason `host`, so a call by tailnet IP is refused: call by name. A present `Origin`, and a `Referer` offered as proof, must name this machine's pinned tailnet names only: loopback, localhost and IPv4-mapped forms stay acceptable in `Host` (for `tailscale serve`) but never in `Origin` or `Referer`, and in the loose mode only `X-FP-Local` or `X-FP-Token` prove (`null` refused on every method; reason `origin`). A `Sec-Fetch-Site` outside same-origin and none gives `fetch-site` (same-site is a page on another port), and every GET but /health needs proof (`_proven`: `X-FP-Local`, or the `X-FP-Token` that gated clients already send), else `unproven-origin`; the routes write nothing except the indexer's `/graph`, which may rewrite its cache file when the vault moved, and stays a GET because the Control's Library tab is its only client. Answers carry `nosniff` and `frame-ancestors 'none'`. The token gate also fails closed: no `serve.token` answers 503 on every route but /health unless `--no-token`, and an unreadable token file aborts startup. There is no proxy-header lock, because `tailscale serve` itself adds such headers. Front them with `tailscale serve`, never `tailscale funnel`.

**What it does not do.** It authenticates no person: a tailnet peer that connects directly and sends none of those headers passes (the Desk, Control and PORTAL have no login), and a compromised tailnet device is inside the perimeter (docs/06:31-33). An `Origin`-less POST passes the `Origin` rule (it is taken for a tool), which leans on browsers always sending `Origin` on a POST. The Desk, Control, PORTAL, the bench and the Scanner compare the `Origin` and `Referer` scheme, host and port, so a page on another File Portal port of the same address is not ours; the feeds compare their pinned names and not the port (the ThinkPad serves no page of its own). None of it was observed in a browser: the browser behaviour above is the Fetch standard's and the lanes' tests model it as request shapes (Inferred). `room_chat.py` was not given these locks (Observed: no `peer_ok` or `bind_ok` in it; token-gated and loopback-bound only).

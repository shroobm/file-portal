## §8 Findings

1. A bench that shows lines cannot see a broken table; only a renderer can — and the vault is a renderer. The bench's own crop split a table for five weeks and every line looked fine (Observed).
2. "Insert after the zone's line" is wrong whenever the zone's line is one row of a run that must stay unbroken; the unit a renderer reads is the run, not the line (Observed in the backup-vs-live render).
3. A drift ledger keyed on the zone line lies once an insertion is placed elsewhere; the record must carry where the lines went (built and tested).
4. Windows' path limit reaches into a sandbox: a copy under the scratchpad failed on a 270-character path and looked like a permissions error (Observed; the short path works).
5. A page served fresh per request is only half a deploy: the live server is the old program until it is restarted, so a route the new page needs 404s until then — the page must degrade and say so (built).
6. A held bundle can leave `held/` with no event in the pipeline's log (Observed: 0d68f0e0's last event is 2026-08-03) — the folder is not the ledger.

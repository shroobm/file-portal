## §5 What the commission turned out to be about

`Observed`, `windows-converter/analyst.py:158` — the analyst's production Ollama body carries:

```python
"think": False,
```

qwen3:8b is a hybrid thinking model. Ollama is told, on every chunk, not to think. `--jinja` makes
llama.cpp apply the model's **embedded** chat template instead of a legacy built-in guess — and
that template's own default for thinking is the open question, not a settled fact.

So the hypothesis under test, stated before the measurement and falsifiable by it: **the 814 vs
1,380–2,048 gap is a thinking-block gap, not a template-parsing gap** — in which case `--jinja` is
necessary but *not sufficient*, and parity additionally requires thinking to be turned off on the
llama.cpp side (`chat_template_kwargs.enable_thinking = false`).

Eliminated cheaply before spending GPU time: **not** a model mismatch. The GGUF room-chat points
at resolves to exactly one Ollama manifest, `qwen3:8b` — same weights on both sides (`Verified`,
`grep -rl <blob-sha> ~/.ollama/models/manifests/` → one file).

The harness measures three arms on the same real chunks of the held Valentine, reusing the
analyst's own `fence()` and `_chunks()` rather than a copy: Ollama `think:false` (production
today), llama.cpp `--jinja` default, llama.cpp `--jinja` + `enable_thinking:false`. It records
completion tokens, stop reason, and the analyst's image fence per chunk.

**Sampling never promotes** (docs/21 rule 2): N chunks measured is `Inferred` about the book,
never `Observed` about all of it.

## §3 The open incident, reconciled — a true reading of a false alarm

`muster exit 1`, HARD clock mismatch. **Not a rewind, not a fork.** Both SHAs are ancestors of
`HEAD` on one line, in this order — `Observed`, `git merge-base --is-ancestor` on each, and
`git log --oneline`:

```
a652781  20:35:10  close: S108 §6 + the 15-item sign sheet          ← the ledger row's SHA
7a1e9f4  20:35:25  docs: Change Ledger row — Desktop S108 (a652781)  ← the row itself, 15s later
307e491            coverage: lever-waiver on SYM050_SLICE            ← LEVERS gate fired during the close
e4d731e  20:46:28  close-phase: writer identity + slice_size         ← GLASS gate fired during the close
2a4fa21            ci: ruff-format the two new status test files     ← CI observed green here
   …25 more…                                                         ← the post-close two-model arc (§7 of S108)
4862be1            S108 §7: the post-close arc, declared              ← HEAD
```

**Cause: the row-vs-final gap, structural.** The ledger row is written *after* the closing commit
and therefore names the SHA that existed *when the row was written*. Any commit the close's own
gates force afterwards lands **below** the row, and the row cannot reach back to name it.
S108 declared this in its §6a rather than leaving it to be discovered, and set the clocks to the
true final `e4d731e`. So **TIME-STATE is right about reality and the ledger row is right about
what it could see** — and `open.sh` compares them for byte-equality, which they can never have.

Same *symptom* as **SYM-028** (a SHA mismatch wearing a rewind's clothing), **different cause** —
that one was ledger row ordering, this one is the row's write-order. Not a rediscovery.

**This will fire again at every open** until either the clocks are re-pointed or the check learns
the descendant rule. It is Rab's protocol, so the fix is his call — carried in §5.
